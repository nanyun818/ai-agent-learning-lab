# 13：没有编造，不等于回答了问题

2026-11-01准备，2026-11-03核验实测。状态：学习者已运行j05双指标，依据一致性1、回答完整性0，有效维度判分2/2、与助教建议2/2一致，原始请求尝试2次。助教只读核验，没有重发模型请求。完整六条DeepEval仍未完成，学习者独立复核待完成。见[脱敏报告](../../reports/deepeval-two-metrics.json)。

## 从熟悉的j05看起

用户问：“如何隔离不同项目的依赖？”

给定资料：“（无资料）”。

候选答案：“缺少依赖隔离方面的资料，无法根据资料回答。”

它没有编造内容，但也没有提供隔离依赖的方法。只问“有无依据”，答案可以通过；再问“是否实质回答了用户问题”，答案不通过。两个结论并不矛盾，因为检查的是不同维度。

## 本节的两把尺子

| 维度 | 明确标准 | j05助教建议 |
|---|---|---|
| 依据一致性 EvidenceConsistency | 正文事实受资料支持；资料不足时如实承认未知也可通过 | 通过 |
| 回答完整性 AnswerCoverage | 是否实质回答问题；问“如何”要提供操作方法，仅拒答不算完成回答 | 不通过 |

作为对照，j01问Mem0用途，资料和答案都介绍长期记忆用途，两个维度的助教建议均为通过。标签是助教预先建议，仍待学习者独立复核，不能当作模型已返回的结果。

AnswerCoverage是我们用DeepEval自带GEval定义的自定义维度，不是其内置TaskCompletionMetric。这里仅评价一份文本回答有没有覆盖问题，不证明命令执行、文件修改、工具使用或整个Agent任务成功。

如果产品规定必须依据给定资料回答，j05诚实拒答可能正是合适的行为。完整性低提示资料/检索存在缺口，不能因此要求模型编造方法。后续应检查资料是否存在、检索是否命中、上下文是否送达，再考虑生成问题；不要只改Prompt让模型强行回答。

## 实验怎样执行

two_metrics.py复用既有j01/j05固定样例和DeepSeekJudge适配器。每条答案分别执行两个GEval指标：

```text
问题＋资料＋候选答案 → 依据一致性裁判 → 判分和理由
问题＋候选答案       → 回答完整性裁判 → 判分和理由
```

第二项不把资料提供给裁判，因为本节有意只测回答覆盖程度；这不是对开放世界事实正确性的评价。参考标签不放进任一裁判提示，仅在判分后比较。资料、候选答案和模型不同层次应继续分清：本例不重新检索，不重新生成候选答案，不评实际Agent Desk输出。

两个指标分别保留分数和理由，不取平均总分，否则“有依据但没回答”可能被一个0.5掩盖。输出中的有效维度判分计数是一次一个维度，不是独立用户题数量；j05只有1条答案、2个维度，正常需要2次裁判请求。

## 运行步骤

使用私人启动指南连接服务器，进入已有的DeepEval独立环境：

```bash
cd /home/ubuntu/ai-learning-lab/evals/deepeval
source .venv/bin/activate
python two_metrics.py --preview
```

默认只看j05。预览显示候选答案和助教建议，不调用模型，也不保存成真实成绩。

真实评分前，如当前终端没有DEEPSEEK_API_KEY，单独执行隐藏输入：

```bash
read -rsp '输入 DeepSeek 密钥后回车：' DEEPSEEK_API_KEY
```

输入并回车后：

```bash
export DEEPSEEK_API_KEY
python two_metrics.py --run
```

默认1条答案×2个指标，正常2次付费裁判请求，硬上限2次尝试；单次500输出token，60秒超时，无自动重试。执行错误停止并保存已有结果，不能充当有效的0分。若改用--case all，两条答案共4次；不要为了查看结果重复--run。

读取本节最近报告：

```bash
python two_metrics.py --report
```

结果保存为results/dimensions-*.json，与旧的deepeval-*.json分开。旧lesson.py --report仍读取旧单指标实验，本节要用two_metrics.py --report。两者都没有自动写入promptfoo网页。

## 看懂结果，而不是追求所有项通过

预期j05依据一致性通过，回答完整性不通过。如果真实裁判不同，先读理由和保存的judge_prompt，复核标准与输入，不修改参考标签来迎合模型。少量案例无法验证裁判普遍可靠。
